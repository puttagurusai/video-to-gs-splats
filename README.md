# Video to 3D scene (Gaussian splat or depth-based mesh) on a small Windows laptop

Turn a phone video of a room or object into a 3D scene that looks like the video. Everything runs locally on one
Windows laptop with a 4 GB GPU, with no Linux, no WSL and no C++/CUDA compiler.

* **Default output: a Gaussian splat** (`.ply`), viewed in the Brush viewer. It looks closest to the video.
* **Alternative output: a textured mesh** (`.blend` / `.glb`) built from monocular depth. It opens in Blender but looks
  clearly worse than the splat (see [Results](#7-results-so-far)).
* **One command or one double-click**: `run_video_to_splat.bat` (all settings at the top, live progress).

> **Status, stated plainly.** Tested on two clips only (a 10 s close-up of a mouse on a cloth, and a 14 s hotel-room
> walkthrough). Quality is judged on held-out frames (see [Reading the quality score](#6-reading-the-result)). Clips
> longer than ~15 s, outdoor scenes and moving people are **not tested**. Items that were written but never run end to
> end are listed in [Known gaps](#11-known-gaps-and-not-verified).

## 2. How it works

```
video --> 1 frames --> 2 camera poses --> 3a Gaussian splat (Brush) --> 4 held-out score + summary
                          |                3b OR depth-based mesh (Blender .blend/.glb)
                          |-- COLMAP + GLOMAP-style global mapper (primary)
                          |-- gates: >= 80 % frames registered AND not depth-flipped
                          `-- DA3 poses (fallback: faster, lower quality)
```

| Stage | Script | What it does | GPU? |
|---|---|---|---|
| 1. Frames | `extract_frames.py` | Keeps the sharpest frame in each window (target `FPS`, capped by `MAX_FRAMES`, never below `MIN_FPS`); applies the phone rotation tag; resizes to 1200 px max side. | no |
| 2a. SfM | `run_sfm.py` | COLMAP SIFT features, sequential matching, global mapper (GLOMAP-style, built into COLMAP 4.2), then undistortion into `colmap\dense`. Stops if fewer than `SFM_MIN_REGISTERED` of the frames register. | no (CPU only here) |
| 2b. Flip gate | `sfm_check.py` | A global-SfM model can reproject well and still be depth-flipped. Compares sparse landmark depth with Depth-Anything-V2 relative depth; Spearman must be below -0.3. | small |
| 2c. Fallback | `da3_reconstruct.py --poses-only`, `export_colmap_dataset.py` | If COLMAP fails a gate, times out, or `POSES=da3`: Depth Anything 3 gives poses, intrinsics and depth. The focal length is re-estimated photometrically (square pixels) and a COLMAP-format dataset with a depth-based start point cloud is written. | yes (about 2.5 GB peak) |
| 3a. Splat | Brush (`tools\brush\brush_app.exe`) | Trains a 3D Gaussian splat with WebGPU (no CUDA toolchain). Every Nth frame is held out for scoring. | yes (about 1 GB) |
| 3b. Mesh | `align_real.py`, `refine_depth.py`, `fuse_aligned.py`, `uv_unwrap.py`, `texture_blend.py`, `obj_to_blend.py` | Monocular depth aligned jointly across views to the COLMAP landmarks, refined by plane sweep, fused with a GPU TSDF, UV-unwrapped in Blender, textured by blending the best views with exposure compensation, saved as `.blend` and `.glb`. (DA3 route: `da3_reconstruct.py` does depth + fusion.) | yes |
| 4. Score + summary | `eval_splat.py`, `run_splat.py` | SSIM / PSNR of the held-out renders against the real frames, then `summary.json`. | no |

Other behaviour of `run_splat.py`:

* **Progress.** The console shows an *estimated* percentage, the current stage and the last log line. COLMAP and Brush
  report no percentage of their own, so the bar is based on typical stage times and can be off.
* **Time budget.** With `POSES=auto` and `TIME_BUDGET_MIN` above 0, if the estimated total exceeds the budget the faster
  DA3 route is chosen up front. The estimate is measured on 125-142 frames and **extrapolated** for longer videos.
* **Resume.** `RESUME=1` skips stages whose outputs already exist.
* **Timeout.** COLMAP is killed after `SFM_TIMEOUT` seconds; `POSES=auto` then uses DA3.

3. **Brush v0.3.0.** Download from <https://github.com/ArthurBrussee/brush/releases> and place `brush_app.exe`, its
   licence and README in `tools\brush\`. Recorded zip SHA-256: `b68e3e9cf052d51bf3ee30776fa5a364de7f2ba13b58443128ff797bb7bcfcd6`.
   `tools\brush\brush_app.exe --version` should print `brush-cli 0.3.0`.

   prints the stage plan and an estimated time without running anything.

## 5. How to run

### Option A (easiest): the bat file
1. Put your video in `video\` (or use a full path).
2. Open `run_video_to_splat.bat` in a text editor and change the variables in the box at the top. Every variable has a
   comment beside it.
3. Double-click the file. A console window shows the settings, an estimated progress bar, the stage and the last log
   line, then the summary. With `OPEN_VIEWER=1` the finished splat opens in Brush.

The bat refuses to reuse an existing `runs\<NAME>` folder unless `RESUME=1` or `FORCE=1`, so change `NAME` for a new run.

| Variable | Default | Meaning |
|---|---|---|
| `VIDEO` | `video\hotel_room.mp4` | Input video (path relative to the bat file, or full path). Required. |
| `NAME` | `hotel_room` | Output folder `runs\NAME`. Empty = video file name. |
| `MODE` | `splat` | `splat` = Gaussian splat; `mesh` = depth-based textured mesh; `both`. |
| `STEPS` | `4000` | Brush training steps. 2000 is about 1 min, 4000 about 1.5 min, 8000 about 3 min on this laptop. |
| `MAX_RES` | `800` | Training image size (long side, px). 800 is safe for 4 GB; 1000-1200 is sharper but heavier. |
| `MAX_SPLATS` | `600000` | Cap on Gaussians. Lower (300000) if the GPU runs out of memory. |
| `HELDOUT_EVERY` | `10` | Every Nth frame is hidden from training and used for the quality score. |
| `FPS` | `10` | Target frames kept per second of video (10 suits a slow walk or orbit). |
| `MAX_FRAMES` | `400` | Soft cap on frames (bounds COLMAP time, roughly 1.5-2.5 s per frame). |
| `MIN_FPS` | `3` | Never go below this many frames per second, even above `MAX_FRAMES`. |
| `POSES` | `auto` | `auto` = COLMAP first, DA3 fallback; `colmap` = COLMAP only (stop if it fails); `da3` = skip COLMAP. |
| `TIME_BUDGET_MIN` | `0` | 0 = no limit. If above 0 with `POSES=auto`, a too-long estimate switches to DA3 automatically. |
| `SFM_MAPPER` | `global` | `global` = GLOMAP-style mapper (fast); `incremental` = classic (slower, more tolerant). |
| `SFM_FEATURES` | `3000` | Max SIFT features per image. |
| `SFM_IMAGE_SIZE` | `1200` | Longest image side used for SIFT (px). |
| `SFM_OVERLAP` | `8` | Each frame is matched with this many following frames. Raise for fast motion. |
| `SFM_BA_ITERATIONS` | `1` | Global-mapper bundle-adjustment rounds. |
| `SFM_CAMERA_MODEL` | `SIMPLE_RADIAL` | Lens model; `PINHOLE` or `OPENCV` are alternatives. |
| `SFM_MIN_REGISTERED` | `0.8` | Fraction of frames COLMAP must register, or the result is rejected. |
| `FOCAL_FACTOR` | `0.72` | Focal-length prior as a fraction of the long side (0.7-0.75 normal phone camera, about 0.5 wide-angle). **An assumption: set it for ultrawide or zoomed video.** |
| `SFM_GPU` | `auto` | `auto` probes GPU SIFT and falls back to CPU if it crashes (it does here); `off` never tries. |
| `COLMAP_EXE` | (empty) | Empty = `tools\colmap-cpu\bin\colmap.exe`. Or a full path to another `colmap.exe`. |
| `SFM_TIMEOUT` | `1800` | Seconds before COLMAP is abandoned. |
| `RESUME` | `0` | 1 = continue an earlier run with the same `NAME`, skipping finished stages. |
| `FORCE` | `0` | 1 = reuse an existing run folder without skipping anything. |
| `OPEN_VIEWER` | `1` | Open the finished splat in Brush. |
| `PAUSE_AT_END` | `1` | Keep the window open at the end. |
| `OUT_ROOT` | `runs` | Folder that holds run folders. |
| `BLENDER` | `C:\Program Files\Blender Foundation\Blender 5.1\blender.exe` | Needed for `MODE=mesh` or `both`. |
| `PYTHON` | `python` | Python with numpy, opencv, torch, scipy, pycolmap, transformers. Use a full path if needed. |

### Option B: the command line
Run from the project folder. `-I` stops Python importing stray local files.
```
python -I scripts\run_splat.py --video video\room.mp4 --name room
python -I scripts\run_splat.py --video video\room.mp4 --name room_da3 --poses da3 --steps 2000
python -I scripts\run_splat.py --video video\room.mp4 --name room_mesh --mode mesh
python -I scripts\run_splat.py --video video\room.mp4 --plan-only --assume-duration 120
```
Options (same meaning as the bat variables): `--mode`, `--fps`, `--max-frames`, `--min-fps`, `--steps`, `--max-res`,
`--max-splats`, `--heldout-every`, `--poses`, `--sfm-mapper`, `--sfm-features`, `--sfm-image-size`, `--sfm-overlap`,
`--sfm-ba-iterations`, `--sfm-camera-model`, `--sfm-min-registered`, `--sfm-gpu`, `--colmap-exe`, `--focal-factor`,
`--sfm-timeout`, `--time-budget-min`, `--blender`, `--force`, `--resume`, `--open-viewer`, `--out-root`, `--name`.
`--plan-only` (optionally with `--assume-duration <seconds>`) prints the plan and time estimate and exits.

### Viewing the result
* **Splat:** `tools\brush\brush_app.exe runs\<name>\splat\export_4000.ply` (number = `STEPS`). Blender shows a splat
  `.ply` only as a point cloud; a Gaussian-splat add-on for Blender 5.1 is an **unverified** option.
* **Mesh:** open `runs\<name>\mesh\scene.blend` in Blender (Material Preview shows the texture) or use `scene.glb`.

### Running the stages by hand
Useful for experiments (paths here are examples):
```
python -I scripts\extract_frames.py video\room.mp4 runs\room\frames --fps 10 --max-side 1200
python -I scripts\run_sfm.py --frames runs\room\frames --work runs\room\colmap --fast --mapper global --focal-factor 0.72
python -I scripts\sfm_check.py --work runs\room\colmap\dense
tools\brush\brush_app.exe runs\room\colmap\dense --total-steps 4000 --max-resolution 800 --max-splats 600000 --sh-degree 2 --eval-split-every 10 --eval-every 4000 --eval-save-to-disk --export-path runs\room\splat --export-every 4000
python -I scripts\eval_splat.py --renders runs\room\splat\eval_4000 --frames runs\room\colmap\dense\images
```
`run_sfm.py` refuses to overwrite an existing `database.db` (use `--reuse-db` to remap it). DA3 fallback by hand:
```
tools\venv_da3\Scripts\python.exe -u -I scripts\da3_reconstruct.py --frames runs\room\frames --out runs\room\da3\scene.ply --poses-only --focal da3
python -I scripts\export_colmap_dataset.py --cams runs\room\da3\scene_cams.npz --out runs\room\dataset --focal auto
```

## 6. Reading the result

`runs\<name>\summary.json` and the console summary contain: frame count, pose source (`colmap/glomap` or
`da3 (fallback)`), notes (for example a rejected COLMAP model), stage timings in seconds, peak GPU memory, and the
held-out scores.

**Quality score.** Every `HELDOUT_EVERY`-th frame is excluded from training. Brush renders it and `eval_splat.py` compares
the render with the real frame: SSIM (grayscale), a blurred "coarse" SSIM (sigma 3) and PSNR. The verdict uses SSIM:

| Verdict | Held-out SSIM |
|---|---|
| GOOD | 0.80 or more |
| FAIR | 0.60 to 0.80 |
| POOR | below 0.60 |

These thresholds are heuristics from our two clips, not a standard. Held-out frames are neighbours of training frames
(the usual splat protocol), so the score measures interpolation between seen views, not views from far away.
Brush run-to-run noise is about plus or minus 0.001 SSIM.

If the verdict is FAIR or POOR, check the summary notes first: a DA3 fallback gives clearly lower quality than COLMAP
poses (controlled test on the mouse clip: 0.39 vs 0.86 SSIM).

### Layout of `runs\<name>\`
```
frames\          extracted frames (jpg)               logs\1_frames.log  2_colmap.log  2b_flipcheck.log
colmap\          database.db, sparse\, dense\         2c_da3.log  2d_export.log  3_brush.log  4_eval.log
dataset\ da3\    DA3 fallback dataset and poses       m1_align.log ... m6_blend.log (mesh mode)
splat\           export_<STEPS>.ply, eval_<STEPS>\    summary.json
mesh\            scene.ply/.blend/.glb (mesh mode)
```

## 7. Results so far

Measured on the laptop above, 4000 Brush steps, 800 px (details and commands in `RUNLOG.md`).

| Clip | Frames | Poses | Total | Held-out SSIM / PSNR / coarse | Verdict | Peak GPU |
|---|---|---|---|---|---|---|
| Mouse (10 s close-up) | 125 | COLMAP accepted | 280 s (frames 6, COLMAP 171, flip check 26, Brush 74, score 2) | 0.845 / 24.9 dB / 0.942 | GOOD | 964 MiB |
| Hotel room (14 s) | 142 | COLMAP rejected by the flip gate after 254 s, DA3 fallback | 454 s | 0.726 / 21.4 dB / 0.890 | FAIR | 1130 MiB |

Mesh mode on the mouse clip (different, partly leaky protocol: the held-out frames were not excluded from fusion or

0.633 vs depth-based 0.726 on the hotel clip).

## 8. Speed: where the time goes

Profile of the mouse clip (125 frames): COLMAP 171 s = feature extraction 20 s + matching 92 s + mapper about 50 s;
Brush 74 s; flip check 26 s (mostly Python/model start-up); frames and scoring 8 s. COLMAP is 55-65 % of a run and is CPU
only here (bundle adjustment is CPU in every COLMAP build; the CUDA build crashes on this laptop).

**Measured finding:** during COLMAP's CPU matching the machine sits at about 10 % CPU (roughly 2 of 22 cores), and
`--FeatureMatching.num_threads` made no difference. Matching is therefore the biggest unused-hardware bottleneck.

Options considered:

| Idea | Status |
|---|---|
| `scripts\parallel_match.py`: split the matching pairs over several COLMAP processes and merge the databases | **Written, NOT tested or wired in.** A test run was interrupted. Needs a run to confirm speed and that the merged database gives the same registration. |
| COLMAP's built-in ALIKED features and LightGlue matching (listed by both local COLMAP builds, models download on first use) | Not tried. Needs a download of unknown size and a separate database (do not mix with SIFT). |
| Run DA3 poses in parallel with COLMAP so a rejected COLMAP result costs no extra wall time | Not implemented. |
| Start the flip check while Brush trains (abort Brush if it fails) | Not implemented; would save about 26 s. |
| FastMap (GPU global SfM replacing the mapper) | **Tried and dropped.** Ran on Windows only through its slow PyTorch path (209 s vs about 50 s for COLMAP's mapper), needed a patch for COLMAP 4.2 databases, and its poses differed from COLMAP's by about 13 degrees median. No Windows port exists. |
| InstantSfM, VGGT-X, InstantSplat | Not tried (installation and memory needs unknown; foundation-model SLAM reportedly needs 8 GB or more). |
| DA3-only route (`POSES=da3`) | Works, about 2.7 min on the hotel clip, but lower quality (SSIM about 0.73). |

Quick levers today: lower `SFM_FEATURES` (2000), `SFM_IMAGE_SIZE` (800) and `SFM_OVERLAP`, lower `FPS`, lower `STEPS`,
or `POSES=da3`. Time for 2-minute videos is **extrapolated only**, never measured.

| Script | Purpose |
|---|---|

| `fuse_aligned.py`, `fuse.py`, `dense_tsdf.py`, `depth_odometry.py` | GPU TSDF fusion and shared helpers. `dense_tsdf.py` and `depth_odometry.py` are also the older stand-alone depth routes. |

| Script | Purpose |

## 10. Capture checklist, limits, troubleshooting

**Capture checklist (most failures start here)**
* Move the phone sideways as well as turning (parallax). Pure rotation in place gives no depth.
* Slow and steady; lock exposure and focus if possible; avoid motion blur.
* Plenty of texture in view; avoid mirrors, glass, screens and blank walls filling the frame.
* Keep people and pets out of the shot; keep the phone upright for rooms.
* Cover each area from two angles; return to the start to help consistency.
* Aim for 100-200 kept frames. Rough guide: up to 20 s `FPS=10`; 20-60 s `FPS=5`; about 3 min `FPS=3`.

**Known limits**
* Tested on two clips; not tested on clips over ~15 s, outdoors, or with moving people.
* Monocular depth is weak on mirrors, glass and blank walls. Metric scale from monocular depth can be off by 2-4x;
  COLMAP scale is arbitrary (the mesh is scaled so median depth = 1, "scene units", not metres). For real size, measure
  one known object and rescale (`--ceiling-height` or `--scale-mult` in `da3_reconstruct.py`).
* The splat is not a mesh and cannot be used for collision or physics.

**Troubleshooting**

| Symptom | Likely cause | Check / fix |
|---|---|---|
| "`runs\<name>` exists" | Run folder already there | New `NAME`, or `RESUME=1` / `FORCE=1`. |
| COLMAP model rejected: "flip check" | Global mapper produced a depth-flipped model (happened on the hotel clip) | Automatic DA3 fallback; for better quality re-capture with more parallax or try `SFM_MAPPER=incremental`. |
| "GATE FAILED: only N % registered" | Too little overlap/parallax, or `SFM_OVERLAP` too low | Raise `SFM_OVERLAP`, `FPS`; re-capture. |
| COLMAP exit code 0xC0000409 | CUDA build GPU path crash | Use `tools\colmap-cpu` (default) or `SFM_GPU=off`. |
| `WinError 1314` while downloading models | No symlink privilege | Download with `local_dir=` instead of the HF cache. |
| Brush runs out of GPU memory | Too many splats or too high resolution | Lower `MAX_SPLATS` (300000) and `MAX_RES` (640). |
| Mesh mode: Blender not found | Wrong path | Set `BLENDER`. |
| `database.db exists` from `run_sfm.py` | It refuses to overwrite | Delete deliberately or pass `--reuse-db`. |
| Resume after an interrupted COLMAP stage fails | A partial `colmap\` folder is not cleaned (known gap) | Delete `runs\<name>\colmap` and resume. |

## 11. Known gaps and not verified

* `run_video_to_splat.bat` and the progress display have **not** been run end to end with the current settings (the
  underlying `run_splat.py` was run end to end on both clips with the same stages).
* The mesh stages (texture, blend) have been run by hand on the mouse clip but not through `run_splat.py --mode mesh|both`.
* `da3_reconstruct.py --focal auto` (used in the DA3 mesh route) has not been exercised through the orchestrator.
* Timings for 2-minute and longer videos are extrapolations (`est_colmap`), not measurements.
* The Brush GPU utilisation is unmeasured (only peak memory was sampled).
* The reason COLMAP's CUDA build crashes on this laptop is unknown.
* `parallel_match.py` and the other speed-ups in section 8 are not tested.
* Visual realism "80 %" is judged by held-out SSIM and by eye; the mouse clip reaches GOOD, the hotel clip only FAIR.
